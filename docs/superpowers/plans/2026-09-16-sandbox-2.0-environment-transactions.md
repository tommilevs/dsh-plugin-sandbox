# Sandbox 2.0 Environment Transactions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add immutable Clone, transactional DSH version switching, Reset/Rollback runtime reconciliation, generalized Replace, recovery points, operation journals, and recoverable Delete without ever merging environment histories.

**Architecture:** Extend the stage-1 `SandboxManager` with an operation coordinator and recovery service. Every destructive operation locks touched environments, captures recovery state, works against immutable source/staging state, validates before activation, and records a transaction journal. Replace copies complete managed state while preserving target identity/history; DSH release mismatches are explicit gates rather than merge problems.

**Tech Stack:** Node.js ESM, `node:test`, Git worktrees, filesystem staging/rename, pnpm, private DSH runtimes.

**Spec:** `docs/superpowers/specs/2026-09-16-dsh-plugin-sandbox-2.0-design.md`

## Global Constraints

- There is no Git merge, cherry-pick, or three-way reconciliation between environments.
- Clone and Replace use an immutable source snapshot captured at operation start.
- Source and target histories remain separate; source `.git` is never copied into a target.
- Replace rejects source == target.
- Managed-to-managed Replace requires identical `dshRelease` values before target mutation.
- Replace to STABLE requires the source to match the currently running STABLE DSH version; Sandbox 2.0 does not downgrade/upgrade the global STABLE executable.
- DSH version switch, destructive Reset/Rollback, Replace, STABLE profile replacement, and Delete create recovery points first.
- Runtime binaries are reconstructed from the environment manifest and are not stored in Git recovery commits.
- Multi-environment destructive locks are acquired in deterministic ID order.
- A failed operation must either restore the pre-operation state or leave an incomplete journal that identifies exactly what recovery still needs to happen.

```js
// lib/operations.js
import { existsSync, mkdirSync, readFileSync, readdirSync, renameSync, writeFileSync } from 'node:fs'
import { randomUUID } from 'node:crypto'
import { join } from 'node:path'

export class OperationCoordinator {
  constructor({ root }) {
    this.root = root
    this.locks = new Set()
    this.dir = join(root, 'operations')
    mkdirSync(this.dir, { recursive: true })
  }

  async withLocks(ids, fn) {
    const ordered = [...new Set(ids)].sort()
    const busy = ordered.find(id => this.locks.has(id))
    if (busy) throw Object.assign(new Error(`Environment is locked by another operation: ${busy}`), { code: 'ENVIRONMENT_LOCKED', environmentId: busy })
    ordered.forEach(id => this.locks.add(id))
    try { return await fn(ordered) }
    finally { ordered.forEach(id => this.locks.delete(id)) }
  }

  write(journal) {
    const file = join(this.dir, `${journal.id}.json`), temp = `${file}.${process.pid}.tmp`
    writeFileSync(temp, JSON.stringify(journal, null, 2) + '\n')
    renameSync(temp, file)
    return journal
  }

  begin({ kind, environmentIds, metadata = {} }) {
    return this.write({ id: randomUUID(), kind, environmentIds: [...environmentIds], status: 'running', phase: 'started', metadata, startedAt: new Date().toISOString(), updatedAt: new Date().toISOString() })
  }

  update(id, patch) { const current = this.read(id); return this.write({ ...current, ...patch, updatedAt: new Date().toISOString() }) }
  complete(id, result = {}) { return this.update(id, { status: 'complete', phase: 'complete', result, completedAt: new Date().toISOString() }) }
  fail(id, error, recovery = {}) { return this.update(id, { status: 'failed', error: String(error?.message || error), recovery, failedAt: new Date().toISOString() }) }
  read(id) { return JSON.parse(readFileSync(join(this.dir, `${id}.json`), 'utf8')) }
  listIncomplete() { return readdirSync(this.dir).filter(name => name.endsWith('.json')).map(name => JSON.parse(readFileSync(join(this.dir, name), 'utf8'))).filter(item => item.status === 'running' || (item.status === 'failed' && item.recovery?.required)) }
}
```

```js
// lib/source-snapshot.js
import { mkdirSync, rmSync } from 'node:fs'
import { join } from 'node:path'
import { randomUUID } from 'node:crypto'
import { readEnvironmentManifest } from './environment.js'

export async function captureManagedSource({ root, environment, commit, git }) {
  const path = join(root, 'operations', 'sources', randomUUID())
  mkdirSync(path, { recursive: true })
  await git(environment.path, ['worktree', 'add', '--detach', path, commit])
  return {
    kind: 'environment',
    environmentId: environment.id,
    commit,
    path,
    profilePath: join(path, 'dsh-home', 'profiles', 'web'),
    manifest: readEnvironmentManifest(path),
    async dispose() {
      await git(environment.path, ['worktree', 'remove', '--force', path]).catch(() => rmSync(path, { recursive: true, force: true }))
    },
  }
}
```

```js
export function createRecoveryRecord({ root, environment, kind, head, release, metadata = {} }) {
  const id = randomUUID()
  const record = { id, environmentId: environment.id, kind, head, release, metadata, createdAt: new Date().toISOString() }
  mkdirSync(join(root, 'recovery'), { recursive: true })
  writeFileSync(join(root, 'recovery', `${id}.json`), JSON.stringify(record, null, 2) + '\n')
```

Algorithm inside `manager.changeDshRelease`:

```js
return this.operations.withLocks([id], async () => {
  const journal = this.operations.begin({ kind: 'change-dsh-release', environmentIds: [id], metadata: { release } })
  const beforeHead = await this.snapshot(id, `Recovery before DSH switch to ${release}`)
  const beforeManifest = this.getEnvironmentManifest(id)

  try {

    // materialize new runtime in operation staging, not over active runtime
    // copy managed profile into staging and update staging manifest
    // reconstruct dependencies against staged runtime
    // validate and boot staged environment
    // atomically activate staged runtime/profile
    // commit environment manifest/profile change
    this.operations.complete(journal.id, { recoveryId: recovery.id })
  } catch (error) {
    await this.restoreRecovery(recovery)
    this.operations.fail(journal.id, error, { recoveryId: recovery.id, required: false })

  }
})
```

- [ ] **Step 4: Implement `VersionMismatchError` and Replace sequence**

```js
export class VersionMismatchError extends Error {
  constructor({ sourceRelease, targetRelease, targetKind }) {
    super(`DSH versions differ: source ${sourceRelease}, target ${targetRelease}`)
    this.code = 'DSH_VERSION_MISMATCH'
    this.sourceRelease = sourceRelease
    this.targetRelease = targetRelease
    this.targetKind = targetKind
    this.allowed = targetKind === 'stable' ? ['change-source', 'cancel'] : ['change-target', 'change-source', 'cancel']
  }
}
```

Managed target algorithm:

```text
capture source commit/worktree
lock source+target in sorted order
stop target
snapshot target recovery
compare sourceSnapshot.manifest.dshRelease with target manifest
copy source managed state into target staging WITHOUT .git/runtime/logs
reconstruct target private runtime/dependencies in staging
validate staged target and real boot
replace target managed working state while retaining target .git
commit "Replace from <source> at <commit>"
complete journal
```

Mismatch comparison happens before copying target working state.
