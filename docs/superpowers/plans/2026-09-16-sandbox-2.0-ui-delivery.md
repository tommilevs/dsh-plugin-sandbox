# Sandbox 2.0 UI and Delivery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the STABLE-centric Sandbox workbench with the Sandbox 2.0 Environment Manager UI, expose version/Clone/Replace/recovery/AI workflows safely, preserve compatible 0.5.x entry points, update localization/documentation, and qualify the 2.0 package.

**Architecture:** Keep the existing single browser entry (`lib/client.js`) because it is loaded through DSH's custom `window.__ModuleLoader__` contract, but reorganize its internal React components around environment-oriented state. Backend RPC remains one authenticated human route; the UI consumes structured version-mismatch errors, pending actions, recovery records, and AI-control state already provided by earlier plans. Compatibility names such as `promote` remain aliases while new UI uses generalized operations.

**Tech Stack:** React through DSH ModuleLoader, Node.js ESM backend, `node:test` contract tests, JSON localization files, GitHub locale validator, npm package/release workflow.

**Spec:** `docs/superpowers/specs/2026-09-16-dsh-plugin-sandbox-2.0-design.md`

## Global Constraints

- Human UI remains usable with AI control Off.
- Environment cards show name/id, exact DSH release, runtime state, plugins, Git state, origin, and validation state when available.
- Replace always shows explicit Source and Target plus both DSH releases before execution.
- Managed-to-managed version mismatch offers target-to-source, source-to-target, or cancel; STABLE mismatch offers source-to-STABLE or cancel only.
- YOLO enabling requires an explicit strong human warning/confirmation; once enabled there are no per-operation model confirmations.
- Safe pending actions require explicit Approve/Deny controls.
- UI terminology is Environment-first; `Promote` remains only as a compatibility affordance during migration.
- English/Russian embedded client copy and canonical locale JSON stay schema-identical; German community locale is updated in the same commit so locale validation remains green.
- README must continue to state that Sandbox is not OS/container/VM hostile-code isolation.
