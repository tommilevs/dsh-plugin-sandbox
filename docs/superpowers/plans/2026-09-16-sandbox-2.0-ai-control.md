# Sandbox 2.0 AI Control Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let models inside STABLE or any managed DSH environment inspect and manage Sandbox through native DSH tools with explicit Off/Safe/YOLO policy, pending human approval in Safe mode, and unrestricted Sandbox administration in YOLO mode.

**Architecture:** Add one human-owned global AI-control setting to the authoritative manager, a centralized model-action policy/pending queue, and a dedicated loopback bridge server with per-child ephemeral tokens. The same model-tool definitions work locally against the STABLE manager or remotely through the bridge from a child environment. Off registers no Sandbox model tools, Safe converts all mutating/code-executing actions into approval requests, and YOLO executes all exposed Sandbox administration operations directly without per-action confirmation.

**Tech Stack:** Node.js ESM, `node:test`, Node HTTP server, `@deepseek-ai/dsh-tools` (`defineTool`, `ctx.tools.register`), DSH Cordis plugin lifecycle.

**Spec:** `docs/superpowers/specs/2026-09-16-dsh-plugin-sandbox-2.0-design.md`

## Global Constraints

- AI control defaults to `off`.
- AI mode is one global mutually exclusive value: `off | safe | yolo`.
- Model tools cannot set or elevate AI-control mode.
- Human UI/API is the only route allowed to change `off/safe/yolo`.
- Off registers no Sandbox management tools for the model.
- Safe allows read-only inspection immediately; every mutation or code execution becomes a pending action requiring explicit human approval.
- YOLO executes every Sandbox capability exposed as a model tool without per-operation confirmation, including operations on any environment and allowed STABLE profile operations.
- YOLO does not bypass engine correctness checks: recovery points, version gates, validation, transaction journals, and locking still run.
- Sandbox AI policy does not revoke unrelated shell/file/computer-use tools separately granted by DSH.
- Child bridge listens on loopback only; tokens are unique per child launch and revoked when that child stops/exits.
- Bridge/model APIs never expose `aiControlSet`.

```js
// lib/ai-policy.js
export const AI_MODES = Object.freeze(['off', 'safe', 'yolo'])
const READ_ACTIONS = new Set(['list', 'inspect', 'history', 'diff', 'listReleases', 'recoveryList', 'operationStatus'])
const MUTATING_ACTIONS = new Set(['create', 'clone', 'snapshot', 'installPlugin', 'start', 'stop', 'validate', 'changeDshRelease', 'reset', 'rollback', 'replace', 'destroy', 'recoveryRestore', 'recoveryDelete'])

export function normalizeAiMode(value) {
  const mode = String(value || '').toLowerCase()
  if (!AI_MODES.includes(mode)) throw new Error(`Invalid AI control mode: ${value}`)
  return mode
}

export function actionPolicy(action) {
  if (READ_ACTIONS.has(action)) return 'read'
  if (MUTATING_ACTIONS.has(action)) return 'mutate'
  throw Object.assign(new Error(`Unknown Sandbox model action: ${action}`), { code: 'MODEL_ACTION_UNKNOWN' })
}
```

- [ ] **Step 3: Implement dedicated loopback server**

Use `node:http.createServer()` and `server.listen(0, '127.0.0.1')`. Supported authenticated routes are internal JSON POSTs:

```text
POST /mode
POST /action   { action, args }
```

Authorization header:

```text
Authorization: Bearer <ephemeral-token>
```

The token map stores only `{ environmentId, issuedAt }`; a token is issued once per child start and revoked on stop/process exit. No `aiControlSet`, pending approval, or human-only method is accepted on this server.

- [ ] **Step 4: Implement bridge client with fail-closed errors**

```js
export function createManagerBridgeClient({ url, token, fetcher = fetch }) {
  async function post(path, body = {}) {
    const response = await fetcher(new URL(path, url), {
      method: 'POST',
      headers: { 'content-type': 'application/json', authorization: `Bearer ${token}` },
      body: JSON.stringify(body),
    })
    const payload = await response.json().catch(() => ({}))
    if (!response.ok || payload.ok === false) throw new Error(payload.error || `Sandbox manager unavailable (HTTP ${response.status})`)
    return payload.result
  }
  return { getMode: () => post('/mode'), call: (action, args) => post('/action', { action, args }) }
}
```

```js
export function childEnvironment(home, inherited = process.env, bridge = null) {
  const env = { ...inherited }
  for (const key of Object.keys(env)) {
    if (key.startsWith('DSH_PLUGIN_SANDBOX_') || /^DSH_(?:PROFILE|PROFILE_DIR|CONFIG|CONFIG_PATH|PATCH)$/.test(key)) delete env[key]
  }
  const result = { ...env, DSH_HOME: resolve(home) }
  if (bridge) {
    result.DSH_PLUGIN_SANDBOX_ENV_ID = bridge.environmentId
    result.DSH_PLUGIN_SANDBOX_MANAGER_URL = bridge.url
    result.DSH_PLUGIN_SANDBOX_MANAGER_TOKEN = bridge.token
  }
  return result
}
```
