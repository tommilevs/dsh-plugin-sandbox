# 🧪 DSH Plugin Sandbox

[English](README.md) · [Русский](README.ru.md)

**Создавай · Экспериментируй · Тестируй · Фиксируй · Сравнивай · Переноси**

**DSH Plugin Sandbox** — это изолированная временная среда разработки и тестирования плагинов для **DeepSeek Harness (DSH)**, состояние которой отслеживается через Git. Она позволяет экспериментировать с плагинами в отдельном окружении DSH, видеть все изменения, откатываться к предыдущим состояниям и переносить проверенный sandbox в стабильный профиль только после валидации.

Главная идея проста: сделать разработку и тестирование плагинов воспроизводимыми и полностью обратимыми, не превращая основной профиль DSH в испытательный полигон.

## Возможности

- **Создание изолированных sandbox-окружений** с собственным `DSH_HOME` и отдельным дочерним экземпляром DSH.
- Запуск с **чистого окружения** либо копирование установленных плагинов и настроек из основного профиля DSH.
- Установка плагинов из **пакета, Git-репозитория или по абсолютному локальному пути**.
- Независимый **запуск и остановка** sandbox-окружения без вмешательства в основной DSH.
- **Валидация** перед переносом изменений в стабильный профиль.
- Создание именованных **Git-снапшотов** состояния sandbox.
- Просмотр **diff** и **Git history**, чтобы понимать, что именно изменилось.
- **Reset** незакоммиченных изменений и **rollback** к предыдущему снапшоту.
- **Promote** проверенного sandbox в `STABLE`; перед переносом автоматически создаётся резервная копия.
- Основной профиль остаётся нетронутым, пока вы сами не примете протестированный результат.

## Типичный сценарий работы

1. Откройте **🧪 Sandbox** внутри DSH.
2. Создайте новый sandbox.
3. Выберите: скопировать плагины и настройки основного DSH или начать с чистого окружения.
4. Установите или измените плагин и запустите его внутри дочернего экземпляра DSH.
5. Создавайте снапшоты, сравнивайте изменения, запускайте валидацию, выполняйте reset или rollback по мере необходимости.
6. Когда результат готов, используйте **🚀 Promote**, чтобы перенести проверенный sandbox в `STABLE`.
7. Перезапустите основной экземпляр DSH, чтобы применить обновлённый стабильный профиль.

## Установка

```bash
dsh plugin --profile web add dsh-plugin-sandbox
```

## Локализация

Sandbox имеет встроенные **английскую** и **русскую** локализации и поддерживает языки сообщества. В репозитории уже присутствует и **немецкая** локализация сообщества.

Режим `🌐 Auto` использует язык браузера, если для него существует подходящая локализация, а иначе переключается на английский.

Каждая локализация состоит из файла строк интерфейса и файла метаданных:

```text
locales/<code>.json
locales/metadata/<code>.json
```

Интерфейс Sandbox помогает установить перевод локально и подготовить изменение для отправки в GitHub. Он также показывает прогресс перевода и подсвечивает строки, которые ещё нужно перевести после изменения английской схемы.

### Как добавить или обновить язык

Для нового языка необходимо добавить и файл перевода, и соответствующий metadata-файл. Для уже существующей локализации сообщества можно изменить только `locales/<code>.json`, если метаданные языка не менялись.

Проверить локализацию локально можно так:

```bash
node scripts/validate-locale.mjs \
  locales/en.json \
  locales/de.json \
  locales/metadata/de.json
```

Pull request'ы с локализациями сообщества проверяет **Locale Guard**. Workflow принимает один файл перевода и, при необходимости, соответствующий metadata-файл, сверяет перевод с канонической английской схемой и не выполняет код из pull request. Исходная английская локализация не участвует в автоматическом community auto-merge. Корректные PR с переводами могут автоматически получить approve и быть добавлены через squash auto-merge после успешного прохождения проверок.

## Граница безопасности

> **Это среда для разработки, а не средство изоляции на уровне операционной системы.**

Плагины по-прежнему выполняются с правами пользователя, под которым запущен DSH. DSH Plugin Sandbox предоставляет отдельное состояние профиля, разделение процессов, историю и откат на базе Git, валидацию, резервное копирование и контролируемый `Promote`. Для действительно враждебного кода используйте полноценную изоляцию на уровне ОС, контейнера или виртуальной машины.
